## What
`pnpm evals -- check` lists 34 near-misses: a check on the test sites that proves part of an eval. For each, either bind it (split or sharpen the book's claim so the check proves it whole, the claim change made in the blueprint first, each with a decision) or record in its binding file why it stays a near-miss. Start with the thin-line journeys (pay an invoice from Frappe, run a world, create an org). Run `pnpm evals -- gaps` for the list. Touch blueprint/ concept folders and packages/evals binding files only; do not edit blueprint/shared/swarm.ts, packages/loop or packages/plan (other runs have them). A frozen claim is rewritten only with a decision, as pnpm frozen requires.
## Why
m1-eval-coverage: 34 checks prove part of an eval and score nothing; binding them is the cheapest real score
## Done when
- pnpm evals -- check: 0 problems, and every near-miss is bound or carries its recorded reason
- pnpm blueprint: 0 problems and 0 gaps
- pnpm frozen: 0 breaches
