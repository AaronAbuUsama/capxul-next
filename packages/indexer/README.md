# @capxul/indexer

The slice-zero Ponder 0.18.6 app. It writes only Postgres `ponder`: real v4 company births, personal-Safe claims, PaymentSent, admitted-token Transfers, Safe ownership/executions/approvals, Hats/wearers, budget projections, AgentOwner events, EntryPoint UserOperationEvent and block progress. It is not the world-cost benchmark and has no PGlite/SQLite/JSON fallback. Equity, escrow breadth and historical execution-state reconstruction are not implemented here yet.

Run `pnpm --filter @capxul/indexer start --schema ponder --port 42069 --hostname 127.0.0.1` with `PONDER_DATABASE_URL`, `RPC_URL`, `DEPLOYMENT_FILE` and `ENTRY_POINT_ADDRESS`. The deployment file is the chain bootstrap's static addresses/genesis block, not application state. `/health` is process liveness; `/ready` is Ponder's completed-backfill readiness. No GraphQL or SQL HTTP API is installed. Core reads Safe-scoped SQL views, not HTTP data endpoints.

Use Postgres 17, a separate world database, and a writer role owning only the `ponder` schema. `@capxul/backend` owns role/schema setup. Stop Ponder before a whole-database snapshot or restore. Restart with exactly the same config/schema to recover; do not use `ponder dev` for acceptance because hot reload deliberately rebuilds tables.

`DEPLOYMENT_FILE` contains `{chainId,usdc,payments,hats,installer,companiesHouse,budgets,agreements,agentOwner,deployedBlock}` with real deployed addresses and a numeric starting block. `ENTRY_POINT_ADDRESS` is the deployment's v0.7 EntryPoint. Native Anvil recovery requires saved `--state` plus `--preserve-historical-states`; the supervisor must await clean exit before copying state. Ponder rewinds/replays the non-finalized tail on restart, so check the expected facts after catch-up as well as readiness. Do not mine extra history on every restart; preparation of a new clockless fixture belongs to bootstrap.

Core binds read-only `app` views through the non-released Party's Safe and both owner session settings. Workers may read all facts; tenants cannot read the raw Ponder schema or mutate projections. `transfers` uses blueprint `from_address`/`to_address`; user-operation nonces are decimal `nonce_key`/`nonce_sequence`.

Hat `max_supply` and `supply` use bigint-backed columns to retain the full contract uint32 range. Direct SQL readers receive decimal strings, including `"4294967295"`, rather than signed PostgreSQL integers. A schema change requires a fresh index replay; it is not a same-build snapshot restore.

`chain_logs` retains SafeSetup, owner/threshold events, SafeMultiSigTransaction (including signatures/additionalInfo), SafeModuleTransaction (module/to/value/data/operation) and ExecutionFromModuleSuccess/Failure. Generic Safe logs admit only the emitting Safe, not its owners' related companies. Typed ApproveHash and execution facts are stored only in their respective tables. Stable log identity uses the receipt ordinal; canonical occurrence ordering uses `(block_number,log_index)` within a chain. `safe_owners` is current block-end state, never a pre-execution snapshot. A historical provider must reconstruct ordered state and handle nested executions; retaining these inputs alone is not proof of that provider.
