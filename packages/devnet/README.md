# @capxul/devnet

The local chain's tools: deploy and verify the v4 contracts, run the proof, and build the seeded state. Modules:

| Module | What |
|---|---|
| `chain` | the one port to a chain (viem) |
| `test-keys` | Anvil's published test keys, by role |
| `protocol` | Companies House, its Roles roles, and the 15 contracts deployed through it (the small version of the old `packages/tools` `companies-house apply` and `protocol deploy|verify`) |
| `company` | a company's life on the real v4 contracts as functions: born under Companies House with its authority installed, departments, hats, budgets, and a wearer's payment with a document hash, refusals named in the blueprint's words. What the test sites' Core calls in place of the stand-in chain (plan task `m2-contracts-under-sites`); its test runs against the seeded chain when `DEVNET_RPC` is set |
| `proof` | the company-life proof that `packages/contracts/bin/prove-core.sh` runs |
| `chain-state` | builds the seeded state's pin from what a recording run touched |
| `devnet` | whole-world recovery: stopped Anvil files, a fenced full-Postgres template, native Frappe database/files/configuration backups and fail-closed restore |

`src/main.ts` is the composition root and the only place that reads the environment, files and argv, and prints:
`deploy`, `verify`, `prove`, `seed-pin`. Run with `node --experimental-strip-types`. Anvil's published test keys only. `pnpm devnet:test`
runs the module tests. `orb/` prepares native Amp toolchains and the pinned local Frappe/Postgres stack (see its README).
`cloud/` keeps the Claude proxy setup. `world-cost/` is a minimal Ponder app
over one world and the harness that measured what Ponder costs per world (`docs/mission/world-cost.md`); it has its own
`npm install`, outside the workspace.

## Whole-world recovery

`src/devnet/door.ts` exposes `saveSnapshot`, `readSnapshot`, and `restoreSnapshot`. A host supplies its snapshot root, code pin, maintenance Postgres connection (`psqlAdmin` needs psql 17), complete world/site inventory, and runtime. `runtime.ts` composes HMAC Core pause/resume, the Core database helpers and the host's process supervisor; `bench.ts` supplies `composeBench(["-f", absoluteComposeFile, ...])` for `packages/bench-image/compose.yaml`, not the old all-in-one spike bench. Compose's usual image/env/volume variables must be present. The Python helper runs offline in `site-admin`; mount the same current app code into every bench service during local development.

The site adapter requires the signed-assertion/pull Frappe boundary: `capxul.world.rewrite` keeps its old four-argument signature and removes old OAuth wiring. Recovery keeps the server Core URL empty; an optional browser Core origin is only for rebasing saved customer approval links. Pair this recovery module with that boundary; the old OAuth/outbound-payment implementation is not supported. A save checks `Runtime.running` before pausing anything and refuses a stopped source without activating it.

For a gateway on a world-specific public port, supply `composeBench(composeArgs, undefined, siteUrl)` where `siteUrl(site)` returns that site's complete customer origin. The offline rewrite applies it to `host_name` after the world rewrite, before any service resumes. Omit it to keep the site's standard port-8000 default; never substitute the private bench/Core origin for the customer origin.

The fourth optional callback `coreUrl?: () => string` supplies the target public Core origin to `world.rewrite` as `browser_core_url`, so saved approval links can be rebased before resume. Supply the same origin to the Core store's `rewriteRestoredWorld`; neither callback enables outbound site-to-Core calls. The third site-origin callback remains unchanged, and may be omitted independently.

The supervisor fences every mutation entrance, including direct chain/bundler access, waits for clean exits, and starts Core paused without running migration. Each store callback must retarget both restricted runtime URLs to `world.database` and close its pools before returning. A single shared snapshot root serializes recovery on the host. The whole shared bench pauses while its writers drain, so another world's sites on that bench pause temporarily too. A stale host lock, bench guard or `restore-pending.json` is an operator-recovery condition, not permission to delete it and start a mixed world.

Snapshots are host-local: the checksummed folder references a nonconnectable PostgreSQL template by name and OID. The template contains every schema and retains database/schema/table ACLs and RLS. It is not a portable database export. Files and encryption keys are sensitive; keep the root private on protected storage and do not upload it unencrypted. Separate restores require new database/directory/site names and new database credentials; saved site encryption keys remain unchanged. Optional `stateDir/site-service/<site>.json` provisioning intents are captured and remapped to the new world/site/filename without changing company, Safe or admin identity. A restore replaces post-cut intents; older worlds without them remain supported, and the site service still checks restored `org_slug`/`safe_address`. In-place restore retains the abandoned database rather than deleting its record branch. Redis jobs must drain before save; browser sessions/cache are invalidated on restore. Only local/simulated worlds are supported.

The real PostgreSQL integration check is opt-in: set `WORLD_SNAPSHOT_PG` to a disposable PG17 maintenance database and run `pnpm devnet:test`. It creates uniquely named fixture databases and roles and removes only those it owns. It checks full-schema data, tenant RLS, Ponder's database CREATE grant, independent clones, in-place abandoned data, oversized file transport, corruption refusal and recovery failures. It does not claim the complete Core/Ponder/Frappe supplier-payment acceptance run.

Archive transport alone uses container root to cross host/container UIDs. It copies through private temporary staging owned by `frappe`, runs native backup/restore as that user, and publishes host-owned mode-0600 files in a mode-0700 directory. Restore mounts the saved bundle read-only. The opt-in native regression uses `WORLD_SNAPSHOT_BENCH` as JSON `{ "composeArgs": ["-f", "/absolute/compose.yaml"], "site": "configured-disposable.localhost" }`; run the test as root or another non-1000 host UID against a configured disposable production bench. It pauses/resumes that bench and checks native database/public/private archives, saved encryption configuration, host ownership and owner-only access.

## World catalogue door

The same `src/devnet/door.ts` exports `migrateCatalogue(admin: Admin): Promise<void>` and `worldCatalogue(query: Admin, secrets: readonly string[]): WorldCatalogue`, plus `WorldRow`, `Command`, `SnapshotRow`, `CatalogueCut`, `CatalogueHistory` and `RestoreCatalogue`. Run the additive migration on the **fresh world's database immediately after Core migrate**, never on `up` or restore. It owns `app.worlds`, `app.world_snapshots` and `app.command_records`, not Core's financial tables. Runtime queries must use `capxul_worker` retargeted to that world database; `capxul_core` has SELECT only. Each query executes its complete SQL string on one connection and resolves only after commit; close pooled connections before template copying. The supplied `psqlAdmin` streams SQL through stdin and parses JSON rows without the former argv/16-MiB transport limits, hiding credential-bearing database errors.

The store exposes `create`, `show`, `cut`, `history`, `append`, `transition`, `save`, `rewrite`, `snapshots`, `records`, `record` and `export`. `create(WorldRow, Command)` begins creating at epoch 1; `transition(worldId, verb, Command)` atomically validates the declared state machine, changes state and appends one entry. Its committed event is in the returned entry's JSON-text `changes.events`: `{event:'world_transitioned',trace_id,from,to,transition,world_id,kind,epoch}`. Publish that authoritative event only after commit, never infer it from successful process startup. Workflow transitions should use `kind:'event'` and `command:null`; public commands use their actual command, actor/hats captured at entry, trace and outcome. `Command` carries epoch-independent timing in milliseconds; the store allocates epoch/sequence/hash under a per-world transaction lock and redacts before inserting. Supply all known secret values, including process-held keys/passwords; public transaction hashes survive. Results above 30,000 UTF-8 bytes retain their redacted byte count and first 2,000 characters.

`cut(worldId): Promise<CatalogueCut>` returns `{epoch,seq,head}` for the **catalogue**, never Core's financial manifest sequence. `history(worldId): Promise<CatalogueHistory>` atomically returns `{lineage,cut,records,snapshots}` including every abandoned branch and retained snapshot metadata, without the list limit. The offline recovery wrapper reads the saved catalogue cut from the installed target database, and for in-place restore reads the complete `history` from the retained abandoned database. It calls `rewrite(targetRow, {sourceWorld,snapshot,cut,abandoned?}, command)` before existing Core/site rewrite and before any resume, without rerunning migration. In-place `targetRow.epoch` must equal `abandoned.cut.epoch + 1`; the store checks the saved cut, shared prefix, gap-free hashes, abandoned head and existing snapshot metadata before importing anything, then enters restoring with a `restore` entry. Snapshots saved after the cut remain listed because their host-local bundles are retained too. After successful runtime recovery call `transition(id,'restored',eventCommand)`. A separate clone instead begins **creating** with its own `born` entry and exact parent fields; call `transition(id,'start',eventCommand)` only after its runtime succeeds. Its source's rows are not changed. Provenance includes the computed public head with a `0x` prefix; cut/hash verification itself uses bare hexadecimal.

`records` supports epoch, actor email, kind, world-time range, trace, abandoned inclusion and a bounded list limit; `export` returns lineage first and all matching rows exactly once, in epoch/sequence order, with `{data,lines,bytes,lineage}`. Public adapters must pick their declared return shape, not print private configuration or add the export body to JSON metadata. The selected devnet runner is `packages/evals/src/modules/devnet/run.sh`; only its three live-schema checks are bound so far. The remaining slice-zero claims are deliberately unbound until their public behavior and same-run proof exist; the native catalogue control is not composed slice acceptance.
