# Local-world supervisor

`packages/cli/src/devnet.ts` composes these host adapters behind the single `capxul world` CLI. It does not use the spike's JSON Core or snapshot registry. Prepare tools/images with `.agents/setup`; **do not start `capxul-stack` or run `amp orb services ensure` alongside this production-shaped layout**.

## Commands

```bash
source packages/devnet/orb/env.sh
pnpm capxul world init slicezero --config var/worlds/slicezero/config.json
pnpm capxul world create --config var/worlds/slicezero/config.json
pnpm capxul world provision harbourline --config var/worlds/slicezero/config.json
pnpm capxul world inspect --config var/worlds/slicezero/config.json --json
pnpm capxul world snapshot save checkpoint --config var/worlds/slicezero/config.json
pnpm capxul world snapshot read checkpoint --config var/worlds/slicezero/config.json
pnpm capxul world snapshot restore checkpoint --config var/worlds/slicezero/config.json
pnpm capxul world stop --config var/worlds/slicezero/config.json
pnpm capxul world up --config var/worlds/slicezero/config.json
```

`init` creates a mode-0600 configuration and fresh MariaDB/site-service credentials. It needs the four development database URLs from `orb/env.sh`; runtime children never receive `PG_ADMIN_URL` or the operator's signing key. Every world uses a separate database, bench Compose project, directories and eleven consecutive loopback ports (default 18000; `CAPXUL_WORLD_PORT_BASE` chooses another range before init). The private Alto port is base + 10; fenced public bundler ingress is base + 9. Older configs without the private port remain readable for retained worlds. One Postgres 17 container is shared per host. Existing foundation containers must not already occupy that Postgres port. Secrets, cookie jars and raw failed-command output remain under the private `var/worlds/<id>` directory, not in receipts or git.

`create` alone creates/migrates the database and binds the indexer views. It copies the native seeded Anvil state, deploys test currency, writes the static deployment manifest and prepares historical blocks before installing the stopped authority clock. The manifest includes flat `budgets`, `agreements` and `agentOwner` addresses from the pinned v4 deployment record, alongside the existing company/installer/payment/hat/token inputs. It then starts the real services. `up` and all restore paths **never migrate or rewrite that manifest**. A creation or restore pending marker fails closed. Unknown payment outcomes require inspecting the existing approval; the CLI does not create a replacement spend.

The configuration and process receipts pin the checkout commit. Commands other than `stop` refuse a different checkout, and startup refuses to reuse a process from another build. Use the matching checkout for a retained world or snapshot; do not relabel an old running process as evidence for newer source. Stop remains available when the checkout changes.

Startup is backing databases/Redis and production bench → Anvil → ready Ponder → optional bundler → site service → paused Core → authenticated Core resume/ready → ingress. Amp owns foreground service lifetimes as `world-<id>-<component>`. A successful `up` exits while these supervised services continue. Ponder launches through its installed executable, not a pnpm parent which exits by signal before the indexer drains. `stop` closes/drains ingress, pauses Core and gracefully stops every world writer; MariaDB/Redis/Postgres data remain. Bench containers use init with process-group signal forwarding rather than relying on PID 1's default signal handling. A failed component stop does not skip the others. PID birth-time and clean-exit receipts prevent a forced-killed Anvil process from being called a safe snapshot cut.

Private service ports must never get portals. Only the fenced ingress ports (`publicCore`, `publicBench`, `publicRpc`, optional `publicBundler`) may be exposed to trusted local-world users. Core `/admin/*` is not forwarded. The HTTP gateway drains mutations, drops WebSockets and closes all entrances together during recovery. This is a trusted-host local development supervisor, not a production network-security boundary.

## Recovery

Save/read/restore delegate to `devnet/door.ts`, `composeBench` and `localRuntime`. Recovery stops all bench writers and performs native encrypted backups/restores offline, while MariaDB/Redis remain up. It snapshots the real Postgres template, native Anvil history, deployment, sites and site-service intents. The store adapter restores authority `clock.json` and closes restricted pools before database cloning. Source `CAPXUL_SECRET` and site encryption keys are preserved; clone MariaDB credentials are fresh. Offline callbacks set the target site's public origin and rebase saved approval links to the target public Core origin in both stores, without restoring legacy server-to-Core wiring. No implicit rekey or schema migration occurs. Only a stopped authority clock is supported here; no running-clock pump is claimed.

Composition creates the transactional world catalogue only on fresh creation, after installing the actual chain clock. `composeWorld().up()` and `.stop()` record lifecycle success after the real host operation; CLI dispatch conversion is a separate Recovery-owned change. Save captures the drained catalogue cut before copying the database and publishes snapshot metadata only after native publication and successful resume. A published snapshot whose resume fails remains a failed operation without a successful catalogue save entry. Restore captures abandoned history before its database is renamed/fenced, then reads and rewrites the actual restored catalogue offline before resuming. In-place restore retains abandoned records and snapshot metadata; a clone names its exact parent catalogue sequence. Financial record heads are never used as catalogue cuts. Missing schema/rows refuse without migration or synthetic backfill. The opt-in `WORLD_COMPOSITION_PG` control requires a fresh disposable PostgreSQL instance; it tests real database copying/catalogue persistence with external process, chain and bench boundaries stubbed, not native full-stack recovery.

For a clone, initialize a different id/port range, then use:

```bash
CAPXUL_WORLD_PORT_BASE=18100 pnpm capxul world init clone --config var/worlds/clone/config.json
pnpm capxul world snapshot restore checkpoint --as var/worlds/clone/config.json --config var/worlds/slicezero/config.json
```

The target must share the source snapshot root, code version and Postgres host. World ids, database names, ports, site names and state directories remain distinct. Snapshots are host-local database templates, not portable exports. A failed restore stays fenced with its marker and abandoned database retained for inspection; there is no automatic destructive reset.

## Slice-zero execution and supplied bundler

Provisioning births/installs the company on v4, grants the founder's personal Safe the shipped admin hat and registers that Director plus a named member with a real claimed personal Safe but no company hat. Directory rows contain EOA `address` and `personalSafe`, never keys. The public signed `org site provision` command then creates/releases the site. Independent bench reads verify Company, Safe-linked Account/Bank Account and the first acknowledged stream/hat user; provision success alone is not readiness. Native bench output decodes structured JSON, bare string scalars and empty None results.

Fresh `create` installs the reviewed local `prepareBundler`/`suppliedAlto` recipe: it funds dedicated executor/utility accounts, deploys MockPaymaster and funds its EntryPoint deposit, persists `paymaster` in `deployment.json` and writes `{argv:[absoluteAltoExecutable],url,env,paymaster}` to the private config before starting the bundler. Orb setup builds the sponsor artifact. This is an on-chain accept-all development mock, not signed sponsorship conformance. The command runs in the foreground with an explicit environment; readiness requires `eth_supportedEntryPoints` to include v0.7. `up` only starts the persisted slot; restore reconstructs it from the saved sponsor with the target's own private RPC/Alto ports and canary keys, never calling `prepareBundler`, redeploying or topping up. Old configs may still have no supplied slot; missing inputs fail inside receipt-first preparation before fixture creation. Slice execution uses the existing `payByUserOp`/`viaBundler` exports directly. `viaBundler` takes a signed PackedUserOperation, not a Core approval. The adapter maps the real collected approval into `payByUserOp`, and requires both the mined transaction hash and a successful real UserOperation hash. It never calls `pay` or `viaEntryPoint` as a substitute.

`pnpm capxul world run slice-zero --slug harbourline --config PRIVATE_CONFIG --json` requires a fresh fixture on the selected created world; do not run the standalone `world provision` example first on that world. Runtime startup may precede the eval run. The gate supplies `--prepare <argv-json-file>` to the harness: it saves the running receipt and same-run status before executing the literal argv, then starts bindings only on successful preparation. The nested `world prepare SLUG` requires the run-lock token, matching running receipt/build/stack and private config/fixture paths. Existing fixture, pending birth or acceptance files are refused rather than relabeled as new actions.

Missing bundler/paymaster inputs are validated inside that receipt-first preparation, not before the harness starts. A failed preparation remains an incomplete attempt with failed/not-run verdicts; it is not a completed supplier run. Unsupported binding worlds must also be recorded fail-closed by the harness without executing the JSON skeleton against this stack; an old harness that refuses them before receipt creation remains a concrete attempt blocker.

Inside that receipt, preparation invokes public provisioning, makes a real submitted invoice/draft payment, requests it as the indexed hat user, waits for Core's asynchronous approval, submits via the supplied bundler, checks posting/reconciliation, then saves/reads/restores through native recovery. It independently compares the restored selected payment and original named GL rows with the pre-save reads. Only then does it mint a native one-time Frappe login for that non-Administrator user. The generated acceptance fixture includes real snapshot/read+replay and reversible Ponder, >300-second delivery and parked-money fault commands. Faults leave the accepted payment untouched; parked-money repair targets the same retained event key.

`CAPXUL_EVAL_RUN_DIR/preparation.json` records `{version:1,run:{id,at,commit},world:{id,epoch},kind:'fixture-preparation-not-journey-proof',phases:[{name,startedAt,finishedAt?,sourcePath?}]}`. Each completed phase points to a credential-sanitized run-relative JSON source under `preparation/`. Partial failure leaves its started phase without a finish/source; it never creates acceptance credentials early. The harness owns `prepare:{argv,exitCode,signal,log:'prepare.log'}` in its receipt and marks failed preparation incomplete without executing binding scripts. This evidence ties fixture actions to the exact attempt, not to older component-proof files.

The gate regenerates `blueprint:slices --journey thin_line --json` and selects **all** `.slices.find(s => s.id === 'slice-0').required`, never the 13-claim floor or a copied ID list. It delegates once to `pnpm evals -- <IDs> --world slice-zero --environment <metadata.json> --prepare <argv-json-file> --json`. Success requires `passed:true`, a complete matching-environment receipt, fresh same-run verdicts for every requested ID, no `fail`/`not_run`, and source-equality captures for all four screens. The eval runner alone writes receipts/scoreboard. Missing bundler inputs, unsupported world bindings, failed preflight or incomplete evidence are not slice success.

The internal `world fixture load|seed|repair` commands are for that disposable acceptance run. Load requires the committed resend baseline to include a payment event, then waits for every same event key/sequence to gain another attempt, a new applied timestamp and an ACK-backed applied state without error. It does not restore again or replace the selected payment. `world fixture resume-arm <consumer> [--event NAME] [--transition KIND]` and `world fixture resume-kill <consumer>` are the `wfl:*/resume` fault mount (`devnet.resume-fault-mount`). An arm with `--event`/`--transition` is taken only by a delivery whose envelope `name`/`props.transition` match; other deliveries pass untouched. Only disposable local worlds give Core the private `faults/` directory. An armed consumer stops after its effect and before its ACK, in the same transaction, and reports its pid. `resume-kill` SIGKILLs that supervised Core child, waits for supervision to restart it paused, resumes it through the signed `world up` path and prints `{consumer,eventId,event,transition,reachedAt,killed:{pid,signal,at},restarted:{pid,birth,codeVersion,readyAt}}`. `resume-disarm <consumer>` withdraws an arm no delivery has claimed and prints `{consumer,state:"disarmed"}`, or `{consumer,state:"none"}` when nothing is armed; a claimed arm is refused, so the caller runs `resume-kill`. When the Core holding a claimed fault has already died, `resume-disarm` and `resume-kill` clear it and print `{consumer,eventId,event,transition,state:"abandoned"}`. It judges nothing: the binding checks redelivery, the same result and exactly one ACK. A private operation lock serializes recovery and the gate; only its token-bearing nested preparation, fixture and inspection commands may enter while the gate owns it. Nested failure causes and raw subprocess output remain private in `last-error.log`; runtime logs are `amp orb service logs world-<id>-<component>`.

## Concept-runner inputs

Every selected concept runner receives `CAPXUL_WORLD_CONFIG` (the absolute private config path), `CAPXUL_ACCEPTANCE_FIXTURE` (the absolute post-restore fixture path), `CAPXUL_SECRET` (Core's diagnostic signing secret), `CAPXUL_WORLD_RUN_TOKEN` (the private nested-command token) and the harness's `CAPXUL_EVAL_RUN_DIR`. The acceptance fixture follows `packages/evals/src/modules/acceptance/fixture.ts`; the real config and cookie jar stay private and must not be copied into evidence. Runtime and fixture identities, rather than separate component-proof files, are the assertion inputs.

Native storage runners additionally receive `CAPXUL_STORAGE_EVAL_DATABASE=databaseUrl(config.database.tenant,config.world)`: the restricted `capxul_core` connection retargeted to the selected world's actual database, never maintenance or worker authority. It remains private environment data, not a receipt field. Runners must correlate the running receipt with `preparation.json`'s run and actual world, public Core readiness and `app.world`; the connection itself does not prove a claim. Supported config/fixture types and readers are exported through `devnet/door.ts`, not imported from supervisor internals.

Public document/report checks additionally inherit `CAPXUL_PRIVATE_KEY` for the selected Director EOA, `CAPXUL_CORE_URL` for fenced public Core, and `CAPXUL_SITES_ACTORS` naming a mode-0600 file outside the run directory. Its exact shape is `{version:1,world:{id,epoch},org,site,director:{name,email,address,personalSafe,privateKey},member:{name,email,address,personalSafe,privateKey}}`. Preparation creates it after trusted registration and refreshes its epoch before final login. The member is checked on chain against the Board/admin hats and receives none. Scripts may use its key for signed refusal/revocation/readback controls, but must sanitize both keys (including unprefixed hex) before saving any output; neither this file nor its key values belong in evidence. A bench-created cookie does not prove public CLI identity. Runtime children still receive neither signer key.

Business timestamps use `worldNow(sql):Promise<number>` from `@capxul/backend/devnet` on the caller's existing SQL connection. It validates the single `app.world.clock` and returns its stopped `nowMs`; missing/malformed clocks fail `INVALID_CLOCK`, and running mode fails `UNSUPPORTED_CLOCK` until an anchored stop authority exists. No consumer extrapolates rate or falls back to host time. Recovery installs the saved instant offline before resuming consumers. Operational deadlines and authentication expiry still use real time.

`world inspect --config "$CAPXUL_WORLD_CONFIG" --json` is read-only and fails unless the pinned foreground processes, public Core readiness, actual database/world/epoch/clock, public Anvil chain and six production bench processes agree. Its JSON has `version`, `observedAt`, `codeVersion`, `stack`, `world:{id,epoch,kind,database,sites}`, `clock`, `lineage`, `records:{seq,head}`, `components:{<name>:{pid,birth,codeVersion}}`, `core` (the actual readiness response), `chain:{chainId,blockNumber,blockHash}`, `bench:[{service,image,running,health}]` and `bundlerConfigured`. The chain number is a decimal string. These are live sequential observations, not an atomic recovery cut, per-eval pass or completed journey receipt. An absent bundler remains explicitly absent.

Trusted bench execution uses argv `['docker','compose',...config.bench.composeArgs,'run','--rm','-T','--no-deps','site-admin','bench','--site',site,'execute',method,'--kwargs',JSON.stringify(kwargs)]`, working directory `config.root`. The explicit private Compose env file is already in `composeArgs`; never serialize credentials as argv. `bench()` and `asPerson()` in `fixture.ts` expose the same native/admin-read and signed hat-user boundaries. Chain identity registration uses private authenticated `POST /admin/org` with the fixture company/Safe/token, named hats and people containing both EOA `address` and `personalSafe`; public provisioning is then the signed `org site provision` CLI.

No new public `doc create`, `doc submit` or `report run` door is provided here. Bench fixture creation cannot prove those CLI claims, nor can trusted world/company fixture setup substitute for exact public journey operations. Sites owns the `jrn:thin_line` / `fun:thin_line` bindings. Their agreed `journey.json` requires the exact twelve blueprint operations in order, public argv/exit/raw output, actors/traces/call IDs, independent source files and native recovery integrity, plus actual correlated emitted success events for the funnel. `preparation.json` deliberately does not claim that contract. Those composite claims remain unproved until all public doors/events and same-run assertions exist. The eval runner's `receipt.json`, sibling `status.json` and retained per-concept evidence under `CAPXUL_EVAL_RUN_DIR` remain the only composed scoring contract.
