# @capxul/backend

Slice-zero Core: durable company directory (no keys), approvals, indexed-fact consumption, ordered site delivery and append-only records. Postgres is mandatory. Ponder owns `ponder`; Core owns `app`; ERPNext owns accounting. This does not implement every blueprint RPC/workflow or the rest of breadth.

`src/shared/door.ts` exports `Mail`, `MailMessage`, `MailError` and `resendMail`. Notices/access inject `Mail.send({to,subject,html?,text?,idempotencyKey})`, returning `{id}`. Resend makes exactly one request, forwards the caller's key unchanged and checks the staging recipient allowlist before transport. It cannot be configured as a devnet sender: devnet supplies its durable world-time sink through the same structural interface. No caller should retry with a new key after an uncertain answer. Local HTTP fault tests validate classification/isolation, not live Resend conformance.

## Personal-Safe service signer

The same shared door exports `ServiceSigner`, `ClaimSend`, `ClaimReceipt`, `ClaimSignerConfig`, `ServiceSignerError`, `claimServiceSigner(config)` and `migrateServiceSigner(admin)`. The adapter takes a restricted worker pool, chain/RPC, operator-supplied viem `LocalAccount`, and the fixed Companies House, Roles, claimer, role and namespace. It accepts only `send({key: 'setup:<personId>:<positiveAttempt>',email,signer}) -> {hash}`. It encodes `Roles.execTransactionWithRole(claimer,0,claim(namespace,email,signer),DELEGATECALL,role,true)`, not caller-supplied transaction bytes. Account setup owns admission and orchestration; this provider does not prove a mailbox or authenticate a person.

One PostgreSQL account lock serializes preparation/signing. Signed bytes and their hash commit before a durable attempted marker, which itself commits before the one broadcast attempt. Same-key/same-input retries recover the stored hash, changed inputs refuse, and a different job cannot use the key while its previous receipt is absent. Unknown broadcast answers throw safe `PROVIDER_ERROR` with the known hash; never resubmit with a new setup attempt. A crash after the attempted marker but before ingress is deliberately indeterminate and is not automatically resent. This favors one-send safety over guessing delivery. Source transaction rollback must not erase these bytes: pass the independent worker pool, never a caller transaction.

`waitForReceipt({key,hash})` reads that exact send, polls once a second for up to 60 seconds across transient read failures, and returns `{hash,chainId,blockNumber,blockHash,status,safe,errorCode}`. A success must include the expected `CapxulSafeClaimed` from Companies House for the recorded Safe/signer. A mined revert is a returned result: exact `SwapRefused` maps to `WRONG_STATE`, `EmailNotNormalized`/`InvalidSigner` to `INVALID_INPUT`, otherwise `TRANSACTION_FAILED`. Historical error decoding uses optional exact-transaction tracing, never a block-end simulation; unavailable tracing retains the generic failure. Pre-send infrastructure failure is safe `PROVIDER_ERROR`. Signed bytes contain the claim mailbox and stay worker-only; they are never event props or diagnostic output.

Run `SIGNER_TEST_ADMIN_URL=… SIGNER_TEST_RPC=… node --experimental-strip-types --no-warnings --test packages/backend/test/service-signer.pg.ts` against a fresh loopback `signer_test` PostgreSQL database and isolated Anvil loaded from `packages/contracts/state/core.json`. The native test uses the actual seeded Companies House service-role member, asserts committed signed bytes before ingress, real role delegatecall and resulting personal-Safe owner, lost-answer and SIGKILL recovery with no second broadcast, exact-key/lane isolation and namespace refusal. This is local provider component evidence, not a paid/live service-key policy proof or the selected Ponder/ERPNext/v4 run. Integrator owns provisioning and workflow mounting; no runtime key fallback is supplied.

## Common transition outbox

`src/platform/outbox.ts` exports `TransitionEvent`, `migrateOutbox(sql)`, `emit(sql,event)`, `readEvent(sql,id)`, `consume(sql,consumer,eventId,effect)` and `relay(db,consumer,names,effect,limit=100)`. Provisioning calls `migrateOutbox` after Core's roles/schema in its own migration transaction; ordinary startup and restore do not migrate. This isolated module does not wire server dispatch or replace financial `app.records`.

The envelope is `{id,name,machine,entity_id,owner_kind,owner_id,actor,trace_id,at,props}`. Source callers supply a stable opaque id for each actual transition occurrence (not just its transition name), its immutable authoritative world-millisecond `at`, and exactly the blueprint event's `props`. `emit` uses the source mutation's same SQL transaction; a conflicting replay never overwrites history. Do not put a mailbox, notice rendering facts or invented common business fields into event properties. Owner metadata is `person`/`organization` with its id, or null/null for an unlisted admission. Actor is the acting principal or null for system work. No organization/principal FK is required. Core's tenant role sees/emits only the exact `app.owner_kind`/`app.owner_id` pair set by Parties' canonical `Database.ownerTransaction`; owner scope is not the authenticated acting person. Trusted pre-principal events use the worker transaction. Neither `app.person_id` nor an organization-only setting broadens this policy.

Composition names each consumer explicitly. Its handler receives `(sameSql,event)` and schedules SQL workflow/feed effects only; `consume` writes that consumer's ACK in the same transaction and returns false on acknowledged replay. Never call a provider inside this handler. `relay` supplies restricted worker transactions and transaction-scoped locks, selecting by missing consumer ACK rather than a high-water cursor so a late-committing source is not lost. `readEvent` is the authoritative retained source read, subject to the same RLS. Events and ACKs are append-only to runtime roles. No generic plugin/handler registry is introduced.

Run the focused control with the Parties owner-transaction foundation (PR50) on a fresh dedicated loopback Postgres 17 database named `outbox_test`: `OUTBOX_TEST_ADMIN_URL=… node --experimental-strip-types --no-warnings --test packages/backend/test/outbox.pg.ts`. It creates the two restricted roles and isolated probe tables, asserts source rollback, consumer effect+ACK rollback/retry, SIGKILL before commit, concurrent relay deduplication, person/org visibility through the actual owner transaction and late commits. It refuses a missing or differently named database; it is not selected-stack acceptance or a replacement for Ponder/v4/ERPNext proof.

## Retained Effect spans

`src/platform/spans.ts` exports `migrateSpans(sql)`, `spanCollector(workerSql,context,errorCodes)` and `readSpans(workerSql,{runId,worldId,traceId})`. Explicit provisioning owns migration after Core roles/schema. Create one collector per request, supplying trusted `{runId,worldId,codeVersion,callId,capxul_env,producer,org_id,actor}` and the canonical error-code catalogue. Install its `tracer` with `Effect.withTracer` around actual `Effect.withSpan` RPC/provider execution, and await `collector.flush()` after that Effect ends, on success or failure. Pass a separate worker pool, never the source transaction: refusal/rollback must not erase its observation. A flush failure is `SPAN_RETENTION_FAILED`, not successful proof; it must not roll back already completed business work.

The retained `CompletedSpan` carries native Effect `name,traceId,spanId,parentSpanId,startedAt,endedAt,outcome,errorCode,attributes` plus that context. Times are host-clock milliseconds for system duration, not transition business time. Propagate a real caller span with Effect's `parent`/`withParentSpan`, not an invented parent record. Only `ownerKind,ownerId,referenceKind,referenceId` identifier attributes are currently admitted; other attributes, arguments, return values, exception messages and span events are not stored. The source table is append-only to the worker and inaccessible to the tenant role. Reads require exact run/world/trace, so retained history cannot satisfy a new attempt by accident.

`SPAN_TEST_ADMIN_URL=… node --experimental-strip-types --no-warnings --test packages/backend/test/spans.pg.ts` requires a fresh dedicated loopback `spans_test` Postgres database. The actual Effect/PG control covers parent/child and external-parent propagation, completed success/error, privacy, run/world isolation, restricted reads and visible retention failure. This is collector component evidence only. Server mounting and provider instrumentation are still composition work; no arbitrary record or caller-authored JSON proves a server span.

## Start

Supply `PG_ADMIN_URL` for explicit provisioning only. `DATABASE_URL`, `WORKER_DATABASE_URL` and `PONDER_DATABASE_URL` point at the same existing world DB with login names `capxul_core`, `capxul_worker`, `capxul_ponder` and their passwords. `pnpm --filter @capxul/backend migrate` creates restricted roles and schema v1. The Core tenant role is neither owner nor BYPASSRLS; every transaction sets `app.org_id` locally. The separate system worker has an explicit policy admission across companies. Ponder cannot write `app`. Runtime never falls back to admin and startup never migrates or imports JSON.

The migration includes `src/parties/schema.sql` before indexer binding. `app.parties` is the sole Safe ownership directory, globally readable, with worker-only writes. Every Party transition emits `party_transitioned` (id `party:<party_id>:<transition>`, the Party's owner, the caller's `trace_id`) on the canonical `app.transition_outbox` in the caller's transaction, so composition must run `migrateOutbox` before any Party write. Released births keep history but no longer reserve their Safe or handle. `src/parties/door.ts` exports `lookup`, `register`, `activate`, `release` and `resolveRecipient`; each takes the caller's `Sql` and never opens or commits a transaction. Every mutation takes a required `now: number` then `trace: string`: composition supplies the transaction's authoritative world-clock instant, not request data, and the request's trace (empty is INVALID_INPUT). Row creation/update and event timestamps use that same instant; replays keep existing times. There is no host-clock business fallback. Opaque ULID generation is separate from business time. `resolveRecipient` takes `{companiesHouse,namespace}` before `now` to derive personal Safes locally; it never calls an RPC. Worker privilege is trusted service authority, not a per-concept writer identity; this alone does not prove the blueprint's complete writer claim.

## Organizations

`src/organizations/schema.sql` (explicit privileged `migrate(sql)` after the outbox, Access, Accounts and Parties) creates the blueprint-shape `organizations`, `org_setups`, `org_deployments`, `org_seat_purchases`, `org_apps`, `org_fdes` and the Seats in `org_members`. Tenants read a row only as a current member (`app.current_member`); the founder also reads their own setup; only the worker inserts or updates; nothing deletes. It refuses to run (`LEGACY_ORGANIZATIONS`) while the shared legacy `app.organizations` still has `site`: composition cuts that table over first and its readers move to their owners' tables.

`src/organizations/door.ts` exports `begin`, `get` and `resume` (`organizations.setups.*`), `readSetupFounder` and `readAdmittedDeployment(sql, {orgId, chainId})` (the MoneyDeployed occurrence the setup admitted at finality, with its log id and numeric officer hats; null until then; member-only for tenants) and `addBoughtSeats`/`returnBoughtSeats` (the seat-purchase procedures). Each takes the caller's Sql after `Access.authenticate` in the request's worker transaction, the world instant and a required trace, and never opens or commits a transaction. `begin` takes injected `SetupServices`: the chain id, the company-Safe derivation config, Accounts' `eligibility` bound to the principal, Media's `requireImage`, the deployment's USD-priced currencies and indexing's Board read. Every input is checked before the first write. Start-up defaults come from `countries.json` (Frappe 16.54 `geo/country_info.json` currency and first zone, ERPNext 16.54 setup-wizard fiscal years); a country with no zone in that data needs an explicit `timeZone`, and one with no currency, or an unpriced one, starts in USD. Its transitions (`party_transitioned`, `org_setup_transitioned`, `org_app_transitioned`, `seat_purchase_transitioned`) go to the canonical outbox with the caller's trace.

`src/organizations/process.ts` is the setup's one durable process (`organizations.setups.set-up`). Composition calls
`advance(db, orgId, services, now, trace)` after `begin`, after `org retry` and whenever a wait may have moved. Each call runs
the next unfinished step: mint, confirm-mint (activate or release the Party), host-fde, deploy, confirm-deploy with
open-install in one transaction, then complete, which seats the founder and the FDE. Sends run outside transactions and
are recorded only if the setup has not moved; each is keyed `org-setup:<org>:<mint|deploy>:<attempt>`, and only a final
reverted receipt moves to the next attempt (organizations.setup-send-attempts). A provider outage is thrown back for the
workflow's retries; the runner passes `{ lastTry: true }` on the last, which stalls it. Chain facts come from injected
indexing reads at finality. Approvals calls `onApprovalTransitioned` (signed → authorize) and `onApprovalEnded`
(organizations.approval-endings; landed records the install transaction and block that completion judges at finality). The signer, indexing,
FDE host, buildMoney and Approvals are all injected; `test/setup-process.pg.ts` proves the process on real PG with
scripted stand-ins, not chain proof.

Component control: `SETUPS_TEST_ADMIN_URL=…/setups_test node --experimental-strip-types --no-warnings --test packages/backend/test/setups.pg.ts`, on a dedicated loopback Postgres 17 database. It uses the real Accounts `eligibility`; its image and Board services are stand-ins, not Media or indexing proof, and nothing in it writes a scoreboard verdict. No test glob or CI job runs it (CI has no Postgres): run it by hand, like the other `*.pg.ts` controls here. `SETUP_PROCESS_TEST_ADMIN_URL=…/setup_process_test node --experimental-strip-types --no-warnings --test packages/backend/test/setup-process.pg.ts` is the process's control, run the same way.

`src/organizations/door.ts` exports `migrate` (Seats, `app.current_member`, `app.caller_safes`), `requireSeat`, `readSeatBySafe` and `callerSafes`. One rule admits a Seat everywhere (`requireSeat`, the Seat RLS, `callerSafes`): an active Seat whose Party is not released, in an Organization whose own Party (`organizations.party_id`) is not released. Component control: `CAPXUL_DISPOSABLE=true ORGANIZATIONS_TEST_ADMIN_URL=…/organizations_<name> node --experimental-strip-types --no-warnings --test packages/backend/test/organizations.test.ts`; `test/organizations-fixture.ts` creates the restricted roles and applies the outbox, Access, Accounts, Parties and Organizations migrations in that order (no legacy Core schema: the target table replaces it).

`Database.transaction(org,run,system=false,owner?)` remains compatible; nonempty legacy `org` defaults to owner `{kind:'organization',id:org}`. `Database.ownerTransaction({kind:'person'|'organization',id},run,system=false)` supports personal scope. The exported `transaction(client,org,run,owner?)` uses that same client. Every transaction locally sets `app.org_id`, `app.owner_kind`, `app.owner_id` and clears `app.person_id`/`app.email`; bearer authentication alone supplies person identity. Owner labels are trusted internal scope, never HTTP identity. Chain admission must join both owner fields to non-released Parties, not infer ownership from a site user. Commit/rollback does not leak local settings to the next transaction.

Start Ponder as described in `packages/indexer/README.md`, wait for its `/ready`, run `pnpm --filter @capxul/backend bind-indexer` with the provisioning admin URL, then `pnpm --filter @capxul/backend start` without admin credentials. Configure `CAPXUL_SECRET`, explicit `FINALITY_DEPTH`, `CHAIN_ID` (84532), `RPC_URL`, `CORE_HOST` (loopback by default), `CORE_PORT` (8787), `CORE_URL` (public gateway origin), `FRAPPE_URL` (8000), `FRAPPE_SOCKET_URL` (9000), `PONDER_URL` (42069) and `CAPXUL_WORLD`. A depth of zero is a disposable Anvil fixture only. Both services must use the same database and chain. Use `CORE_HOST=0.0.0.0` only behind the private gateway/firewall when a Docker bench must call Core.

The standalone server mounts `@capxul/site-service`'s signed public `/org/site/provision` handler before consuming the body. `SITE_SERVICE_URL` and `SITE_SERVICE_TOKEN` are required; the private service stays loopback-only. Its trusted Core callbacks use loopback and `CAPXUL_SECRET`. Register the chain-born company via `/admin/org` before provisioning; delivery stays unreleased until site identity is confirmed.

`people` registration rows are `{email,name,address,personalSafe?}`: `address` is the signing key's address, never its private key; `personalSafe` is the person's hat-wearing Safe. Both return from `/admin/org-info`. When present, the Safe, not the key, resolves a hat grant/revoke and scoped UserOperation reads. A direct-key fixture can omit `personalSafe`. Ordinary later incoming Transfers use `deposit_received`, never founder capital.

`GET /health` checks database connectivity. `GET /ready` also requires schema v1 and Ponder readiness. Internal POST routes authenticate HMAC-SHA256 over the raw body via `X-Capxul-Signature`; trace travels in `X-Capxul-Trace`. They are service/operator boundaries, not public anonymous RPCs. No signing key, popup or OAuth stand-in is hosted here.

## Recovery boundary

Each fact's stable receipt-ordinal identity, approval settlement, record append and gap-free company sequence commit together. Each delivery holds a company DB lock until its acknowledgement is saved. Lost acknowledgement causes redelivery: the site's durable event key prevents a second accounting effect. A generic HTTP 200 is not an acknowledgement. Parked money stays visible as an alert, not successful delivery.

`POST /admin/snapshot/pause` closes mutating ingress, stops new work, drains active attempts and returns record heads. `/admin/snapshot/resume` is idempotent. The supervisor must then stop Core and Ponder to release DB connections before template cloning. Devnet's snapshot owner captures the whole database, chain, MariaDB/files and clock; Core restart alone does not prove whole-world recovery.

`CORE_START_PAUSED=true` starts with `/health` 200, `/ready` 503, no Socket.IO collector connections and no deliveries until authenticated resume. The `@capxul/backend/devnet` export provides `Database(tenantURL,workerURL)`, `updateWorldClock(db,{nowMs,clockMode,rate})`, `readSnapshotCut(db)`, `rewriteRestoredWorld(db,{worldId,epoch,clock,lineage,sites,coreUrl?})` and `exportAbandonedBranch(db)`. Close pools with `db.close()` before cloning. Restore rewrites both the organization site and saved request sites; approval identity and hashed records remain unchanged. Optional `coreUrl` replaces only the scheme/authority of saved answer URLs for the mapped organizations, preserving path/query/fragment; empty/omitted leaves URLs unchanged. While both components remain paused, the adapter must also call the site's `world.rewrite` with the same public origin as `browser_core_url` to rebase its saved answers and document links before resume (decision `plugs.answer-origin`). Ordinary restart replays the complete saved answer, including its original URL, regardless of changed `CORE_URL`. Never migrate/rebind on restore: copy the entire stopped database, including Ponder sync/checkpoints and database ACLs, then restart the same Ponder build/schema.

`/admin/alerts` returns host-time ISO `observedAt` and exactly `indexer_unready`, `delivery_stuck`, `money_event_parked`. Their rows include numeric/null `head`, `chainHead`, ISO/null `lastAdvanceAt`; pending count and ISO/null `oldestDueAt`; or ordered `{event_key,kind,reason}` parked events. Index readiness fails closed; a stalled index behind the chain fires after 60 seconds, due unacknowledged delivery after 300 seconds. `/admin/retry-parked` reruns the site's saved event and only clears the durable parked state after explicit successful ACK.

## Component proof

In a fresh, migrated disposable world with the real v4 deployment, run `node --experimental-strip-types packages/backend/test/seed.ts` with `CAPXUL_DISPOSABLE=true`, named `CAPXUL_WORLD`, `CORE_PROOF_DIR` and `RPC_URL`; start Ponder on its emitted deployment file and bind the views. `pnpm --filter @capxul/backend test:integration` then tests actual payment facts, two SIGKILL/lost-ACK windows, replay, RLS, parked repair, alert thresholds, personal-Safe attribution and later deposits. Its receiver implements only the site wire protocol. It is not ERPNext, a bundler proof, a screen receipt or whole-world acceptance.
