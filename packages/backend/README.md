# @capxul/backend

Slice-zero Core: durable company directory (no keys), approvals, indexed-fact consumption, ordered site delivery and append-only records. Postgres is mandatory. Ponder owns `ponder`; Core owns `app`; ERPNext owns accounting. This does not implement every blueprint RPC/workflow or the rest of breadth.

## Start

Supply `PG_ADMIN_URL` for explicit provisioning only. `DATABASE_URL`, `WORKER_DATABASE_URL` and `PONDER_DATABASE_URL` point at the same existing world DB with login names `capxul_core`, `capxul_worker`, `capxul_ponder` and their passwords. `pnpm --filter @capxul/backend migrate` creates restricted roles and schema v1. The Core tenant role is neither owner nor BYPASSRLS; every transaction sets `app.org_id` locally. The separate system worker has an explicit policy admission across companies. Ponder cannot write `app`. Runtime never falls back to admin and startup never migrates or imports JSON.

The migration includes `src/parties/schema.sql` before indexer binding. `app.parties` is the sole Safe ownership directory, globally readable, with worker-only writes and an append-only transactional `party_events` outbox. Released births keep history but no longer reserve their Safe or handle. `src/parties/door.ts` exports `lookup`, `register`, `activate`, `release` and `resolveRecipient`; each takes the caller's `Sql` and never opens or commits a transaction. Every mutation takes a required final `now: number`: composition supplies the transaction's authoritative world-clock instant, not request data. Row creation/update and event timestamps use that same instant; replays keep existing times. There is no host-clock business fallback. Opaque ULID generation is separate from business time. `resolveRecipient` takes `{companiesHouse,namespace}` before `now` to derive personal Safes locally; it never calls an RPC. Worker privilege is trusted service authority, not a per-concept writer identity; this alone does not prove the blueprint's complete writer claim.

`Database.transaction(org,run,system=false,owner?)` remains compatible; nonempty legacy `org` defaults to owner `{kind:'organization',id:org}`. `Database.ownerTransaction({kind:'person'|'organization',id},run,system=false)` supports personal scope. The exported `transaction(client,org,run,owner?)` uses that same client. Every transaction locally sets `app.org_id`, `app.owner_kind`, `app.owner_id` and clears `app.person_id`/`app.email`; bearer authentication alone supplies person identity. Owner labels are trusted internal scope, never HTTP identity. Chain admission must join both owner fields to non-released Parties, not infer ownership from a site user. Commit/rollback does not leak local settings to the next transaction.

Start Ponder as described in `packages/indexer/README.md`, wait for its `/ready`, run `pnpm --filter @capxul/backend bind-indexer` with the provisioning admin URL, then `pnpm --filter @capxul/backend start` without admin credentials. Configure `CAPXUL_SECRET`, explicit `FINALITY_DEPTH`, `CHAIN_ID` (84532), `RPC_URL`, `CORE_HOST` (loopback by default), `CORE_PORT` (8787), `CORE_URL` (public gateway origin), `FRAPPE_URL` (8000), `FRAPPE_SOCKET_URL` (9000), `PONDER_URL` (42069) and `CAPXUL_WORLD`. A depth of zero is a disposable Anvil fixture only. Both services must use the same database and chain. Use `CORE_HOST=0.0.0.0` only behind the private gateway/firewall when a Docker bench must call Core.

The standalone server mounts `@capxul/site-service`'s signed public `/org/site/provision` handler before consuming the body. `SITE_SERVICE_URL` and `SITE_SERVICE_TOKEN` are required; the private service stays loopback-only. Its trusted Core callbacks use loopback and `CAPXUL_SECRET`. Register the chain-born company via `/admin/org` before provisioning; delivery stays unreleased until site identity is confirmed.

`people` registration rows are `{email,name,address,personalSafe?}`: `address` is the signing key's address, never its private key; `personalSafe` is the person's hat-wearing Safe. Both return from `/admin/org-info`. When present, the Safe, not the key, resolves a hat grant/revoke and scoped UserOperation reads. A direct-key fixture can omit `personalSafe`. Ordinary later incoming Transfers use `deposit_received`, never founder capital.

`GET /health` checks database connectivity. `GET /ready` also requires schema v1 and Ponder readiness. Internal POST routes authenticate HMAC-SHA256 over the raw body via `X-Capxul-Signature`; trace travels in `X-Capxul-Trace`. They are service/operator boundaries, not public anonymous RPCs. No signing key, popup or OAuth stand-in is hosted here.

## Recovery boundary

Each fact's stable receipt-ordinal identity, approval settlement, record append and gap-free company sequence commit together. Each delivery holds a company DB lock until its acknowledgement is saved. Lost acknowledgement causes redelivery: the site's durable event key prevents a second accounting effect. A generic HTTP 200 is not an acknowledgement. Parked money stays visible as an alert, not successful delivery.

`POST /admin/snapshot/pause` closes mutating ingress, stops new work, drains active attempts and returns record heads. `/admin/snapshot/resume` is idempotent. The supervisor must then stop Core and Ponder to release DB connections before template cloning. Devnet's snapshot owner captures the whole database, chain, MariaDB/files and clock; Core restart alone does not prove whole-world recovery.

`CORE_START_PAUSED=true` starts with `/health` 200, `/ready` 503, no Socket.IO collector connections and no deliveries until authenticated resume. The `@capxul/backend/devnet` export provides `Database(tenantURL,workerURL)`, `updateWorldClock(db,{nowMs,clockMode,rate})`, `readSnapshotCut(db)`, `rewriteRestoredWorld(db,{worldId,epoch,clock,lineage,sites,coreUrl?})` and `exportAbandonedBranch(db)`. Close pools with `db.close()` before cloning. Restore rewrites both the organization site and saved request sites; approval identity and hashed records remain unchanged. Optional `coreUrl` replaces only the scheme/authority of saved answer URLs for the mapped organizations, preserving path/query/fragment; empty/omitted leaves URLs unchanged. While both components remain paused, the adapter must also call the site's `world.rewrite` with the same public origin as `browser_core_url` to rebase its saved answers and document links before resume (decision `plugs.answer-origin`). Ordinary restart replays the complete saved answer, including its original URL, regardless of changed `CORE_URL`. Never migrate/rebind on restore: copy the entire stopped database, including Ponder sync/checkpoints and database ACLs, then restart the same Ponder build/schema.

`/admin/alerts` returns host-time ISO `observedAt` and exactly `indexer_unready`, `delivery_stuck`, `money_event_parked`. Their rows include numeric/null `head`, `chainHead`, ISO/null `lastAdvanceAt`; pending count and ISO/null `oldestDueAt`; or ordered `{event_key,kind,reason}` parked events. Index readiness fails closed; a stalled index behind the chain fires after 60 seconds, due unacknowledged delivery after 300 seconds. `/admin/retry-parked` reruns the site's saved event and only clears the durable parked state after explicit successful ACK.

## Component proof

In a fresh, migrated disposable world with the real v4 deployment, run `node --experimental-strip-types packages/backend/test/seed.ts` with `CAPXUL_DISPOSABLE=true`, named `CAPXUL_WORLD`, `CORE_PROOF_DIR` and `RPC_URL`; start Ponder on its emitted deployment file and bind the views. `pnpm --filter @capxul/backend test:integration` then tests actual payment facts, two SIGKILL/lost-ACK windows, replay, RLS, parked repair, alert thresholds, personal-Safe attribution and later deposits. Its receiver implements only the site wire protocol. It is not ERPNext, a bundler proof, a screen receipt or whole-world acceptance.

## Isolated agent, document and media storage

`agents/door.ts`, `documents/door.ts` and `media/door.ts` export concept migrations for the integrator's existing provisioning transaction. They do not migrate at runtime or mount themselves. Access' real `app.principals` schema must precede agents; organizations' authoritative `app.caller_safes()` must precede documents. Agents currently supplies the table and scoped reads only, not ordinary create/settle writers. Hosted FDE provisioning is parked; no host, key source or setup workflow is supplied here.

Documents' `store(sql,input,worldNow)` shares its subject's checked-out transaction. New Core stores admit memo, invoice, terms and receipt, never payslip/salary-slip. Historical row/wire vocabulary stays; salary readers remain Frappe HR's permissioned door. New envelopes explicitly use canonical v1 encoding, not an old-wire compatibility claim; independent `cast` ABI/hash vectors are pinned in `documents/documents.test.ts`. `get` and `verify` require current participation even when owner tenancy admits an internal subject read.

Media's `upload(sql,input,runtime)` and `expire(sql,runtime)` require `runtime.now = worldNow` and a transactional `runtime.transitioned(sql,props,at)` callback to the shared outbox. Composition must wrap each in a transaction and bind one stable `file_transitioned` identity per file/transition; an outbox failure must roll back the file mutation. No separate concept outbox or wall-clock fallback exists. `get(sql,fileId)` is anonymous, returns only kept images and returns null for a missing/private file. Identity bytes expire at their persisted 30-minute deadline. The integrator owns authenticated upload/read routes, anonymous image serving and the worker's due-row dispatch; these exports alone are not mounted public operations.

`node --experimental-strip-types --no-warnings --test packages/backend/src/documents/*.test.ts packages/backend/src/media/*.test.ts` checks encoding/admission. The native storage tests additionally require `CAPXUL_STORAGE_PROOF_DATABASE`, and refuse anything but a loopback database named `agents_proof`. Media uses a transactional test sink and storage-level caller labels. Documents checks subject rollback/replay with an empty-Safes negative fixture when the real helper is absent; the entire test, helper and schema roll back. Neither supplies bearer/Seat/outbox acceptance. The three standalone eval runners inspect live selected-world schema using `CAPXUL_STORAGE_EVAL_DATABASE` (restricted `capxul_core`), `CAPXUL_CORE_URL` and an already-running `CAPXUL_EVAL_RUN_DIR/receipt.json`. They never migrate or seed, and refuse missing/JSON receipts. Only schema checks have full bindings; denied table writes are near-misses, not proof of complete writer/authority/lifecycle behavior. None of these component checks replaces the complete dynamic selected-stack gate.
