# Accounts runtime

`door.ts` exports permanent mailbox admission, source reads, eligibility and personal Safe setup transitions. Apply `accounts/schema.sql` after Access and common outbox. Every mutation uses the existing caller-owned worker Sql and authoritative numeric world time, never a nested checkout/commit. `admit(sql,{email,via,ref},trace,now)` is for invitations, escrow money waiting and FDE guest authority facts. The caller checks that authority first; admission and the originating fact commit or roll back together. A repeated admission changes nothing. Public individual waitlist/referral operations remain parked by `cut.individuals-parked`.

Notices reads `readAdmissionForEvent(sql,entityId)` using the committed outbox envelope's opaque entity ID, including pre-principal/unlisted mailboxes. The result includes `mailbox`, `admitted_by`, `referrer_email` and `referral_rewarded_with_invite`. Events contain only the declared transition props, never a mailbox or fictitious organization. The private source-key table is routing metadata, not an event transport. Principal reads are Access-owned; Party names are Parties-owned.

`startSetup` requires a real authenticated person, Parties profile guard, admission or beta gate and valid signer. It changes only setup state, not the chain or Party directory. `observeClaim` verifies actual code and sole ownership; `finishSetup` requires the collection owner's ended-approval proof. These transitions are **not** a complete durable claim workflow: constrained service-signer persistence/broadcast/receipt recovery, Ponder wait, welcome funding and escrow/approval orchestration still require actual provider integration. Do not give them workflow/binding credit before that path runs.

Native regression: provision an isolated Postgres database named `/access_*` and an isolated Anvil loaded from the committed `contracts/state/core.json`, then run `CAPXUL_DISPOSABLE=true ACCESS_TEST_ADMIN_URL=... ACCESS_TEST_RPC_URL=... node --experimental-strip-types --no-warnings --test packages/backend/test/access-accounts.test.ts`. The chain control creates an actual Safe-owned AgentOwner account and proves/rejects signed challenges against its real ownership; it is not a public actor fixture or claim sender. The in-memory Mail and profile guard are labeled component controls, not public/provider acceptance. No selected-stack claim follows from these tests.
