# Board source adapter

This tranche implements proposal/officer intent creation and authenticated route dispatch, not a mounted public service or completed Board54 lifecycle. Composition owns the worker transaction, real dependency mounts and explicit provisioning. No shared server, startup or migration composition is changed here.

`door.ts` exports:

- `migrate(sql)`, `readProposal(sql,orgId,proposalId)` and `readOfficerChange(sql,orgId,changeId)`.
- `propose(sql,context,input,trace?)`: same-Sql Board proposal plus its first `Approvals.open` and canonical source event. `Propose` contains `org_id,opener,subject_kind,subject_id,kind,rejects,calls,note,payment,summary`. Budgets uses `opener:'budgets',subject_kind:'budget-change'`; agents uses `opener:'agents',subject_kind:'agent-change'`. Each opener owns its subject and calls. No raw propose HTTP endpoint exists.
- The propose result is `{proposal_id,nonce,safe_tx_hash,approval_id,url,step:'approve'|'execute',opened}`. Retrying an opener/subject answers the existing proposal and first approval. The caller must propagate errors so its intent, proposal, approval, carrier and events commit or roll back together.
- `requireDirector(sql,orgId,context,live=false)`: real Seat and feature admission plus indexed Director authority; `live=true` pins Safe owners/threshold/nonce, Gate thresholdConfig and signer validity to one RPC block. The configuration stays bigint through the InstallerMoney clamp/ceiling calculation. This is current planning, never a historical settlement snapshot.
- `routeBoard(sql,authorization,path,input,world,trace?)`, `boardPaths`, `BoardWorld`, `BoardContext`, `BoardDoors` and `BoardFacts`. Paths are proposal get/list/approve/reject and officer get/grant/revoke. Real opaque bearer authentication supplies the actor; a body actor is ignored. Seat admission precedes company scope, including for worker execution. The adapter never opens/commits a transaction, signs or invokes a provider to send money.

`BoardDoors` requires actual Access `authenticate`/`requireFeature`, Organizations `requireSeat` and Approvals `open`. There are no fallback guards. `BoardFacts` requires same-Sql admitted deployment, current Safe, Director wearers, indexed hash approvals, officer capacity and office-conflict readers. These consumer interfaces do not implement or certify providers. There is no private-table fallback; in particular no editable `app.hats`/Hat.details native-role inference. The deployment callback must preserve the exact finalized installation's company Safe, Gate and numeric hat identities, admitted for this Organization/chain by the source owners.

Public officer/rejection planning uses its live authority/nonce throughout creation, rather than replacing it with an older indexed snapshot. Calls are call-only; a multi-call proposal uses the world's MultiSendCallOnly. Execute carriers remove lapsed signers before execTransaction. A future payment holds only the execute approval through `send_after`; approveHash is immediate. Approvals owns canonical SafeOp packing, sponsorship, signing and delivery; this module adds no executor.

`proposal_transitioned` is retained in the common outbox with props `{from,to,transition,proposal_id,org_id,kind,nonce,opener,subject_kind,subject_id}`. Officer props are `{from,to,transition,change_id,org_id,change,permission,proposal_id}`, never a Seat, mailbox or note. `readProposal` is a source read, not a terminal reader that proves chain finality.

`carryNonce(sql,world,{orgId,chainId,safe,nonce},at,trace?)` is `board.proposals.carry`, woken by the safe-executions key `(chain_id,safe_address,safe_nonce)`; `orgId` is only the company scope Board's tenant policy needs, which composition takes from Organizations. In the worker's own transaction it settles every proposal of that Organization still waiting at exactly that key. Its own hash executes it (or fails it), a Capxul rejection's hash rejects it, and any other hash replaces it. A board-opened officer change is applied only when that transaction's indexed Hats facts move its hat to (grant) or from (revoke) the member's Safe; otherwise it ends. `approved_by` is the indexed ApproveHash owners at the execution block plus, for the proposal's own hash, the execution's msg.sender when it is one of the proposal's Directors: the execute carrier signs for itself with v=1, which emits no ApproveHash. Each Director's still-unsigned approval is withdrawn through Approvals' real `withdraw`. Before the nonce's execution is final nothing is written, a second run settles nothing, and a different key wakes no other proposal. `listProposalWaits(sql,orgId,chainId)` only enumerates one Organization's waiting keys, so composition can resume them after indexed progress. `CarryWorld.facts` is the historical `SettlementFacts` contract (finalized `execution` at a nonce with its msg.sender and threshold, `approvalsAt` a block and `hatMoved` in a transaction), always read at `CarryWorld.finality`, the one finality depth. `boardFacts(readers, {client, hats})` and `settlementFacts(readers)` compose those facts from the source owners' readers (`BoardReaders`): Organizations' `readAdmittedDeployment` and Core's `readSafeOwnersAt`, `readHatAt`, `readHatWearersAt`, `readSafeApprovals`, `readSafeExecution`, `readHatTransfersInTx` and `readWearerHatsAt`, injected by composition. Planning reads are current at the indexed head; settlement reads are finalized and log-backed, with sender and threshold taken from the execution's own SafeL2 additionalInfo, never from a later Safe-state projection. Officer hats stay null until the admitted deployment binds them, so grant and revoke refuse WRONG_STATE (board.officer-hat-unbound); no install order or Hat details are read as a permission. `hasOffice` is a worn company hat whose details begin `office:` (board.people-hat-role-conflict). Core refuses a module-ruled hat (an Elections clone moves wearers with no Hats event); Board then reads Director wearers (`isWearerOfHat`) and officer hat supply (`viewHat`) live from Hats. For an office hat Core answers `wearing: null` (module-ruled), `hasOffice` reads `isWearerOfHat` live for that hat only; allowance hats are never probed. The company hat readers need the worker role or the session of the Organization that owns the company Safe (its non-released Party, which Organizations registers, carries that `safe_address`); every Board path sets that Organization's session first.

## Component validation, not acceptance

`test/board-mutations.test.ts` accepts `BOARD_TEST_DATABASE_URL` only for the dedicated loopback `board_proof` database with `CAPXUL_DISPOSABLE=true`. `BOARD_PEER_SOURCE` points at an explicitly assembled published-peer backend source tree; the test imports its real Access, Organizations and Approvals doors. The isolated tree never enters delivered source. Chain/deployment/RPC facts in this control are fixtures, clearly not Ponder/v4 authority or public signing proof. `test/board-storage.test.ts` separately checks exact schema/indexes and restricted-role storage behavior.

The standalone `packages/evals/src/modules/board/run.sh` validates the same running selected-world receipt/live runtime before read-only storage observations. Its six schema/writer entries in `evals/bindings/board.json` are **near only**, with no active binding or pass credit. The legacy grant lifecycle binding in organizations.json is unchanged and not duplicated. The complete dynamically regenerated gate still requires one real Postgres/Ponder+ERPNext+v4 run, after authoritative dependencies are mounted.
