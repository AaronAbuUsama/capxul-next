# Sites selected-stack checks

`run.sh` invokes the real single CLI and independently reads native ERPNext through the runtime's non-Administrator cookie. It requires a running receipt on Postgres/Ponder/ERPNext/v4, the exact pinned build and world/epoch, and runtime's mode-0600 `CAPXUL_SITES_ACTORS` file outside the evidence directory. Director and member Access tokens are used only in private child environment and redacted; neither tokens nor optional retained keys enter argv, records or evidence. EOA/privateKey fields are not admission authority and no private key is passed to document commands.

The private successor contract is `{version:2,run:{id,at,commit},world:{id,epoch},org,site,director,member}`. Each actor retains `email` and `personalSafe` and adds `access:{token,personId,safe,expiresAt,kind:'person'}` from actual public Access `verifyCode` and `current` after restore. `safe` must match its `personalSafe`; Director and member have different person IDs and tokens. Version1/missing access, stale run identity and mismatched world/build refuse before public mutations. Runtime owns producing fresh original-person sessions and rechecking active Seats/native grants; private fields are only a transport container, never authority. Core reauthenticates every request and checks its current Seat and canonical expiry; the runner does not infer expiry from host wall time. No session, principal or hat is fixture-seeded.

Epoch comes from the same run's `preparation.json` and its `preparation/restored-world.json` source: run id/at/commit, actual world id/epoch and private config/actors must agree. Preparation is only stack attestation, never journey evidence. `/ready` verifies actual world, readiness, Postgres and Ponder; it has no invented epoch/clock field. A selected receipt's `slice-zero` label is not the actual world id. Symlinks and prefix-lookalike paths cannot put the private actor file inside retained evidence.

Current checks cover public draft creation/readback, native validation and role refusals, signed-out refusals, ordinary invoice submission and balanced public/native GL, mutation replay versus wrong-state refusal, exact success/error shapes, and report access. Fixture documents only supply existing native item/company references, refusal targets and independent reads; newly asserted mutations are made through the public CLI after the running receipt exists. Sanitized invocations and source readbacks stay in that receipt's `sites/` directory. `evals/bindings/sites-public.json` declares only these scoped checks; declarations are not passes until this script runs in the composed receipt. Held submission/return and whole-world report equality remain near-only. Budgets, spans, writer exclusivity, held-payment settlement, feature-off behavior, screen interactions and journey/funnel events remain unbound until their complete controls exist. Acceptance's thirteen floor bindings are untouched.

**Unproved component checks, in no gate.** Two suites run outside any eval run and credit no binding: `packages/backend/test/sites-store.pg.ts`, the Sites store, RLS and atomic events on a disposable loopback Postgres, and `bench --site SITE execute capxul.tests.product_door.run` / `.field_permissions`, native receipts, GL, refusals, permlevel and masking on reads, replays and reports, after a hat is revoked. They are not run on the selected stack, because `field_permissions` creates and drops DocTypes, Reports and a User, which must not happen in a retained evidence world. Their results are component evidence only.
