# Sites selected-stack checks

`run.sh` invokes the real single CLI and independently reads native ERPNext through the runtime's non-Administrator cookie. It requires a running receipt on Postgres/Ponder/ERPNext/v4, the exact pinned build and world/epoch, and runtime's mode-0600 `CAPXUL_SITES_ACTORS` file outside the evidence directory. Director and member keys are used only in child environment and redacted with and without `0x`; no keys enter argv, records or evidence.

The actor contract is `{version:1,world:{id,epoch},org,site,director:{name,email,address,personalSafe,privateKey},member:{name,email,address,personalSafe,privateKey}}`. Runtime owns its production and chain/directory registration. The runner never makes a fake actor or uses a bench command instead of a public operation.

Epoch comes from the same run's `preparation.json` and its `preparation/restored-world.json` source: run id/at/commit, actual world id/epoch and private config/actors must agree. Preparation is only stack attestation, never journey evidence. `/ready` verifies actual world, readiness, Postgres and Ponder; it has no invented epoch/clock field. A selected receipt's `slice-zero` label is not the actual world id. Symlinks and prefix-lookalike paths cannot put the private actor file inside retained evidence.

Current checks cover public draft creation/readback, native validation and role refusals, signed-out refusals, ordinary invoice submission and balanced public/native GL, mutation replay versus wrong-state refusal, exact success/error shapes, and report access. Fixture documents only supply existing native item/company references, refusal targets and independent reads; newly asserted mutations are made through the public CLI after the running receipt exists. Sanitized invocations and source readbacks stay in that receipt's `sites/` directory. `evals/bindings/sites-public.json` declares only these scoped checks; declarations are not passes until this script runs in the composed receipt. Held submission/return and whole-world report equality remain near-only. Budgets, spans, writer exclusivity, held-payment settlement, feature-off behavior, screen interactions and journey/funnel events remain unbound until their complete controls exist. Acceptance's thirteen floor bindings are untouched.
